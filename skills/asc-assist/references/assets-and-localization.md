# Assets and localization

## Confirm the locale matrix first

Record the primary locale and exact ASC locale variants, not only a language count. Separate listing localization, screenshot language, product/subscription localization, and languages actually available in the app. Map requested language/region variants to current ASC support; ask before substituting an unsupported variant.

For each locale and device family, track required text fields, URLs, screenshot count and order, product fields and intentional exceptions. Treat fallback as a visible decision rather than silently marking a missing localization complete. Preserve requested language style, legal meaning, product terminology and paid/free boundaries; adapt phrasing rather than blindly translating keywords.

## Choose a real asset source

Ask which Codex and/or Antigravity connection or workflow is available for generation and rendering, and whether existing screenshots, logos, fonts and design references are ready. Discover accessible capabilities and resource limits. Do not claim to have generated images through another product without evidence.

Prefer authentic screenshots from the confirmed build or demonstrably matching app UI. Capture supported device configurations with test data. Generated illustrations and marketing treatments must not fabricate UI, features, system badges, rankings, endorsements or unsupported functionality. Clearly label conceptual mockups as internal drafts; do not upload them as authentic app screenshots.

When cross-agent work is available and authorized, hand off a minimal English brief containing verified features, locale matrix, brand rules, real UI sources and required outputs. Exclude credentials, private user data and unnecessary source files. If no connection exists, prepare the same file-based brief for the user and validate returned files. Do not assume delegation tools exist.

Look up current Apple requirements for supported devices, screenshot dimensions, counts, formats, previews and app icons when applicable. Resolve per-device requirements from the actual app/platform and official guidance. The in-app icon normally comes from the build; do not promise that a listing upload replaces it.

## Generate and check the deliverables

- Keep source screenshots, composited output and locale-specific copy associated with a known build and revision.
- Render translated text with appropriate fonts and direction, including RTL where requested. Check glyph coverage, clipping, safe areas, readability, device framing and consistency with app behavior.
- Validate file existence, pixel dimensions, format, count and ordering against current specifications. Use available deterministic tools for these checks rather than judging dimensions from appearance.
- Inspect the rendered assets visually. If the current environment cannot render or view them, report the limitation and obtain visual evidence from the user before claiming visual QA.
- Avoid fixed numeric prices or region-specific claims unless approved and accurate for the intended locales and territories.

## Required HTML preview gate

Create a local HTML mockup using the actual proposed asset files and localized metadata. Include a locale selector or grouped locale sections, relevant device groups, screenshot order, copy and URL previews, build identity, revision, and any missing items. Make missing coverage visible. A representative single-language preview does not approve every other locale.

Use local assets and escaped text; do not embed secrets, demo logins, customer data, remote trackers or uploads. Keep the preview responsive and inspect it through an available browser/rendering capability. It is an approval aid, not a claim of pixel-identical App Store rendering.

Ask the user to approve the concrete revision and covered locales before uploading its assets in either preparation mode. Capture the answer. Changes to copy embedded in screenshots, app UI, locale coverage, ordering or other material visual content invalidate the affected approval; rerender and obtain approval for the changed set. Continue independent checks while waiting.

## Read-back verification per locale

After saving, re-open or fetch every requested ASC locale and applicable product localization. Compare each field to the approved content and limits, inspect saved asset counts/order and processing status, and visually check uploaded screenshots when supported. Verify language/region mapping and URL values; detect unexpected primary-language fallback, duplicate languages, missing RTL handling, truncated copy and saves to the wrong locale.

For each item record expected value/artifact, observed saved value/evidence and match status. Platform-normalized values may be accepted with a documented reason; do not silently ignore differences. An upload response or successful Save alone does not establish read-back verification. If remote inspection is unavailable, mark the item saved but unverified or manually reported, as the evidence warrants.
